# Vocab iOS App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native iPhone and iPad version of the Vocab web app, ready to prepare for the App Store.

**Architecture:** SwiftUI app in `ios/`. All behaviour lives in small pure Swift types with unit tests, ported from the web app's tested JavaScript; views only render that state. Word lists are exported from the web app's JS files to bundled JSON, so there is one source of truth.

**Tech Stack:** Swift 5 language mode, SwiftUI, XCTest and XCUITest. No third-party packages.

**Spec:** the web app in `App/` (behaviour and look), `docs/superpowers/specs/2026-11-25-vocab-app-design.md`, and the user's request of 2026-11-27: "this app is for anyone trying to improve vocabulary. build the ios app".

## Global Constraints

- iPhone and iPad, deployment target iOS 17.0. Only the iOS 26.5 simulator runtime is installed, so older versions are compile-checked only.
- Offline. No network calls, accounts, analytics or third-party code.
- Light appearance only, matching the web app: ink `#3d2463`, accent `#7c3fb5`, strong accent `#6b2fb3`, muted `#6e5798`, button gradient `#a177f0`→`#6b2fb3`.
- Helvetica, scaling with Dynamic Type. Sizes 11/13/15/16/18/20/30/56. Corner radii 20/14/10.
- Start page has no bottom bar. Every other screen has: Learn, Revise, Revisit, Calendar, About.
- Copy follows the web app, except web-only install and Safari wording.
- Words are identified by deck **and** id, so the 14 words in both decks are independent (the web app shares them).
- Bundle id `io.github.krsubham48.vocab` (can only be changed before the first App Store upload).
- Release blocker, recorded not solved here: the Advanced deck appears to be SparkNotes' list.
- Do not commit or push without the user asking.

## Review Focus

- State file unreadable or from another version → app starts with empty progress and keeps a copy of the old file.
- App left open across midnight or a month change → "learnt today" and the calendar use the current date.
- Largest accessibility text sizes → every screen scrolls; nothing is clipped or unreachable.
- Every word in a deck learnt → a completion message, and New Word does no harm.
- A word that is in both decks → learning or removing one leaves the other alone.

## Changes made while building

- Revisit uses `List`, not a lazy stack: at the largest text size, scrolling past an
  opened card could leave SwiftUI laying out forever. Covered by
  `testScrollingAnOpenCardAtTheLargestTextSize`. The calendar uses a plain `Grid`.
- At accessibility text sizes, paired buttons, start page links and word rows stack.
- Added `AppModel.isDeckComplete` for the "every word learnt" state.
- At the user's request, the Advanced deck was replaced (iOS only) with an original
  list: `scripts/advanced_words/` plus `scripts/generate_ios_advanced_deck.py`.
  The web app keeps its old list, so people's learnt words there are unaffected.
- Store preparation: About links to `App/privacy.html` and `App/support.html`
  (required inside the app), and shows the CMU Pronouncing Dictionary licence.
  Listing text is in `ios/AppStore/`; `scripts/ios_screenshots.py` takes screenshots.
